# AGENTS.md

Minute of Silence — a Tauri 2 desktop app (Rust backend + React/TypeScript frontend) that lives in the system tray and runs Ukraine's daily national minute of silence at 09:00 (NTP-corrected). It pauses other media players, plays an audio preset, shows an overlay, then restores playback.

This is a memorial app: be conservative with anything that changes *when* or *whether* the ceremony fires, what audio plays, or what text is shown to users. Do not touch the audio files, voice names, or the Ukrainian wording without being asked.

Docs: `README.md` (features, build), `docs/architecture.md` (design + ceremony data flow), `CONTRIBUTING.md` (commits, PRs), `SECURITY.md`, `CHANGELOG.yaml` / `CHANGELOG.md`.

## Commands

Run from the repo root unless noted. Node 20+/22, Rust 1.85+ (edition 2024).

```bash
npm ci                       # install frontend deps
npm run tauri dev            # full app with hot reload (needs system deps on Linux, see README)
npm run typecheck            # tsc --noEmit
npm run lint                 # eslint, --max-warnings 0
npm run build                # tsc + vite build (frontend only)

cd src-tauri
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all             # CI runs this; no network needed (the ntp test only constructs the service)
```

Before finishing any change, run what CI runs: `typecheck`, `lint`, `cargo fmt --check`, `cargo clippy`, `cargo test`. All must be clean (warnings are errors). CI covers Rust on Linux, Windows and macOS, so cfg-gated code must compile on all three.

In a headless/cloud sandbox you usually cannot run `tauri dev` or build the full bundle. Verify with typecheck/lint/fmt/clippy/tests instead, and say what you could not run.

## Layout

- `src/` — React 19 + Fluent UI frontend. `App.tsx` is the root (event listeners, tabs); `components/` holds tabs and `Overlay.tsx`; `utils/api.ts` wraps shared Tauri IPC calls (some components invoke commands directly); `types.ts` mirrors Rust types; `locales/{en,uk}.json` are UI strings.
- `src-tauri/src/core/` — business logic: `scheduler.rs` (1 s loop, compensation + grace windows), `ceremony.rs` (start/finish flow), `audio.rs` (rodio, presets), `ntp_service.rs`, `settings.rs`.
- `src-tauri/src/app/` — Tauri glue: `commands.rs` (IPC), `tray.rs`, `apng.rs`.
- `src-tauri/src/platform/{windows,linux,macos}/` — OS code behind the `Platform` trait in `platform/mod.rs` (volume, mute, media pause/resume, autostart, theme). Selected via `cfg(target_os)`.
- `src-tauri/locales/{en,uk}.toml` — backend strings (`rust-i18n`: tray, notifications).
- `src-tauri/Strings/` — Windows MSIX resources (`.resw`/`.pri`). `src-tauri/audio/` — bundled `.ogg`.
- `src-tauri/tests/` — Rust integration tests. `snap/`, `flatpak/`, `appxmanifest.xml`, `winapp.yaml` — packaging. `src-tauri/gen/` is generated by Tauri; don't edit it by hand.

## Conventions and gotchas

**Rust**
- No `unwrap()` in production paths (use `?` / `AppError`); doc-comments on public items. Existing violations exist (e.g. `ntp_service.rs`, `app/mod.rs`) — don't add new ones.
- Shared state is `AppState` (`Arc<Mutex<Inner>>`). Keep lock scopes short and never hold the lock across an `.await`.
- OS-specific behaviour goes in the matching `platform/<os>/` module and, if shared, through the `Platform` trait. When you change one OS, check the other two still compile and behave consistently.
- Media pausing is targeted (SMTC on Windows, MPRIS/zbus on Linux, AppleScript on macOS). Do not reintroduce global media-key emulation (see `docs/architecture.md`).

**IPC contract (three places must change together)**
1. `#[tauri::command]` in `app/commands.rs`, registered in `generate_handler![]` in `lib.rs`.
2. A typed wrapper in `src/utils/api.ts`.
3. Types in `src/types.ts` mirroring Rust structs (`Settings` is `camelCase` via serde). New plugin APIs may also need an entry in `src-tauri/capabilities/default.json`.

Backend→frontend events are plain strings (`ceremony-start`, `ceremony-end`, `ntp-synced`, `status-updated`, `update-available`, `anthem-start/end`, `resume-from-sleep`); grep both sides when renaming.

**Settings** — persisted through `tauri-plugin-store` (`settings.json` store) and read from both Rust and the frontend. Adding a field: update `Settings` + defaults in `settings.rs`, `DEFAULT_SETTINGS` and the type in `src/types.ts`, UI in `SettingsTab.tsx`, and keep `#[serde(default)]` so old files still load.

**i18n** — every user-visible string needs both languages. Frontend: add the key to `en.json` *and* `uk.json` (they currently have identical key sets; keep it so). Backend: `en.toml` *and* `uk.toml`. Fallback language is Ukrainian. Windows store strings live in `Strings/{en-US,uk-UA}/resources.resw`.

**Changelog** — `CHANGELOG.yaml` is the source of truth for the in-app Changelog tab; entries reference keys under `changelog.*` in both locale files. `CHANGELOG.md` is the human-readable mirror. For a user-visible change, update all of: `CHANGELOG.yaml`, `CHANGELOG.md` (Keep a Changelog format), and the locale keys in `en.json` and `uk.json`. Allowed categories: added, changed, fixed, removed, deprecated, security.

**Version bumps** — the version appears in: `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`, `snap/snapcraft.yaml`, `appxmanifest.xml` (4-part, `X.Y.Z.0`), `flatpak/*.metainfo.xml` (`<release>`), `README.md` (install examples), plus changelog files. `Cargo.lock`/`package-lock.json` update via tooling. Only bump when asked.

**TypeScript** — strict mode with `noUnusedLocals/Parameters`; unused args need a `_` prefix; no `any` without a comment explaining why (CONTRIBUTING); prefer `const`.

**Dependencies** — Dependabot manages npm, cargo and GitHub Actions weekly. Don't hand-edit lockfiles; don't add dependencies for things the platform or existing crates already cover (binary size is tuned with `opt-level = "s"`, LTO, `panic = "abort"`).

## Testing notes

- Rust tests: `src-tauri/tests/{scheduler,settings}_test.rs`, plus a unit test in `ntp_service.rs`. `scheduler_test.rs` re-implements the window logic locally rather than importing it, so changing `core::scheduler` does **not** make those tests fail — update the mirror and add real coverage.
- `npm test` (vitest) is defined but there are no frontend test files and CI does not run it. Pure helpers such as `utils/nearbyDateSelection.ts` and `utils/changelog.ts` are good candidates if you add some.
- Scheduling/time logic: test boundaries (exactly 09:00:00, one second before/after, grace/compensation edges, DST, wake-from-sleep) and never depend on the wall clock or network.

## Git and PRs

- Conventional Commits: `feat|fix|chore|docs|test|refactor|perf|ci(scope): Subject` (examples in CONTRIBUTING).
- One logical concern per commit. Never mix unrelated changes (e.g. a fix + a refactor, formatting, or a dependency bump) in one commit; split them. File count doesn't matter — files that belong to the same change (e.g. Rust command + `api.ts` + `types.ts`, or code + locales + changelog) go together.
- CONTRIBUTING says to branch from and open PRs against `develop`; CI/release run on `main`. Check which branches exist before opening a PR.
- Never push to `main`. Don't commit `.env*`, signing keys, `*.snap`, build output (`dist/`, `src-tauri/target/`).
- Release/updater signing uses secrets (`TAURI_SIGNING_PRIVATE_KEY`) and a baked-in public key in `tauri.conf.json`; never change the updater endpoint/pubkey or workflows' permissions without being asked.
- Security issues are reported privately (see `SECURITY.md`) — don't write exploit details in public issues/PRs.

## Known doc inconsistencies (don't "fix" silently)

- README's Project Structure is slightly stale (e.g. it omits `src/utils/nearbyDateSelection.ts`, and lists `CONTRIBUTING.md`/`index.html` descriptions loosely). Treat the actual tree as authoritative.
